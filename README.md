# Виджет расписания пар

Android-виджет с расписанием группы 26о-090303-ПИ/1 (РОСБИОТЕХ): следующая пара
с обратным отсчётом и список пар на сегодня.

## Состояние

| Этап | Статус |
| --- | --- |
| 1. Парсер расписания в `schedule.json` | готов |
| 2. Автообновление через GitHub Actions и GitHub Pages | workflow написан, репозиторий на GitHub ещё не создан |
| 3. Android-виджет (Kotlin, Jetpack Glance) | не начат |
| 4. Уведомление за 10 минут до пары, пометка изменённых пар | не начат |

## Откуда берётся расписание

Вуз ведёт расписание в системе ММИС. У неё есть открытый API на сайте деканата,
вход в личный кабинет для него не нужен:

- `https://dekanat.rosbiotech.ru/api/raspGrouplist?year=2026-2027` — список групп с кодами;
- `https://dekanat.rosbiotech.ru/api/Rasp?idGroup=<код>` — расписание группы на семестр.

Почему API, а не экспорт `.ics` из личного кабинета:

- `.ics` из кабинета — снимок примерно на месяц, который надо скачивать вручную после входа;
- API отдаёт весь семестр, не требует пароля и содержит больше полей
  (номер пары, признак замены, время последнего обновления расписания).

Экспорт `.ics` при этом пригодился как независимая проверка парсера, см. ниже.

## Парсер

Нужен только Python 3.10 или новее, сторонних пакетов нет.

```bash
python parser/build_schedule.py
```

Команда находит код группы по названию, скачивает расписание, проверяет результат
и пишет `public/schedule.json`. Параметры:

| Параметр | Назначение |
| --- | --- |
| `--group "название"` | другая группа (по умолчанию 26о-090303-ПИ/1) |
| `--group-id 18521` | задать код группы напрямую, без поиска по названию |
| `--out путь` | куда писать результат |
| `--input файл` | собрать из сохранённого ответа API, без сети |
| `--save-raw файл` | сохранить исходный ответ API для разбора проблем |
| `--allow-empty` | разрешить расписание без занятий (каникулы) |

Если сайт недоступен, ответ не похож на расписание или в нём нет занятий, парсер
завершается с ошибкой и не трогает существующий `schedule.json`. Так сбой на сайте
вуза не затрёт рабочее расписание пустым файлом.

## Формат schedule.json

```json
{
  "schemaVersion": 1,
  "group": { "id": 18521, "name": "26о-090303-ПИ/1" },
  "academicYear": "2026-2027",
  "timezone": "Europe/Moscow",
  "generatedAt": "2026-11-12T22:27:39+00:00",
  "sourceUpdatedAt": "2026-11-12T18:01:29+03:00",
  "range": { "from": "2026-09-07", "to": "2026-12-25" },
  "lessons": [
    {
      "id": 17057880,
      "date": "2026-11-13",
      "weekday": 5,
      "slot": 2,
      "start": "10:25",
      "end": "11:55",
      "subject": "Программирование",
      "type": "lab",
      "subgroup": 1,
      "room": "В-6-08",
      "teacher": "Ястребова Ольга Дмитриевна",
      "teacherShort": "Ястребова О. Д.",
      "week": 11,
      "weekParity": "odd",
      "substitution": false
    }
  ]
}
```

| Поле | Значение |
| --- | --- |
| `generatedAt` | когда парсер собрал файл (UTC) |
| `sourceUpdatedAt` | когда расписание последний раз обновляли на сайте вуза |
| `id` | код занятия в системе вуза, постоянный; по нему потом будем искать изменения |
| `date`, `start`, `end` | дата и время по Москве (`timezone` в шапке файла) |
| `weekday` | день недели, 1 — понедельник |
| `slot` | номер пары в сетке звонков |
| `type` | `lecture`, `practice`, `lab` или `other` |
| `subgroup` | номер подгруппы или `null`, если пара для всей группы |
| `week`, `weekParity` | номер учебной недели и её чётность (`odd` / `even`) |
| `substitution` | `true`, если в расписании вуза пара отмечена как замена |

Решения, которые стоит знать:

- **Пары привязаны к датам, а не к шаблону «чётная/нечётная неделя».** Расписание
  вуза не циклическое: недели заметно различаются, бывают разовые пары и субботы.
  Виджету достаточно взять пары с сегодняшней датой. Чётность недели сохранена как
  справочное поле.
- **Тип и подгруппа вынесены из названия.** В исходных данных это одна строка,
  например `лаб Программирование, п/г 2`. Записи без типа (кураторский час)
  получают `type: "other"`, название остаётся целиком.
- **В файле обе подгруппы.** Фильтрация по своей подгруппе будет в настройках
  виджета: так один и тот же файл подходит всей группе.
- **Время без смещения, часовой пояс один на файл.** В Москве нет перевода часов,
  а виджет будет считать время через `Europe/Moscow`, даже если телефон в другом поясе.

## Проверка

Тесты парсера на сохранённом образце ответа API:

```bash
python -m unittest discover -s parser/tests -v
```

Сверка с календарём из личного кабинета. Выгрузи `.ics` из кабинета в корень
проекта как `calendar.ics` и запусти:

```bash
python parser/compare_ics.py calendar.ics public/schedule.json
```

Скрипт сравнивает каждое событие календаря с `schedule.json` по времени, предмету,
типу, подгруппе, аудитории и преподавателю и проверяет, что за те же даты в
`schedule.json` нет лишних пар. На выгрузке от 13.11.2026 совпали все 68 событий.

## Автообновление

Файл [.github/workflows/update-schedule.yml](.github/workflows/update-schedule.yml)
запускает парсер на серверах GitHub и публикует результат на GitHub Pages. Виджет
будет забирать расписание по адресу:

```
https://phtdl3.github.io/schedule-widget/schedule.json
```

Как это устроено и почему:

- **Запуск дважды в день**, в 06:17 и 19:17 по Москве, плюс при каждом изменении
  парсера и вручную кнопкой Run workflow. Вечерний запуск нужен, потому что вуз
  выгружает расписание около 18:00, и изменения на завтра появляются вечером.
- **Репозиторий публичный.** GitHub Pages на бесплатном тарифе работает только с
  публичными репозиториями, а GitHub Actions в публичных репозиториях бесплатны и
  не расходуют месячный лимит минут.
- **Сбой не ломает опубликованное.** Если сайт вуза недоступен, сборка падает до
  публикации, и на Pages остаётся прошлый `schedule.json`. GitHub пришлёт письмо о
  неудачном запуске.
- **`schedule.json` не хранится в git.** Он публикуется напрямую как сайт, без
  коммитов, поэтому история репозитория не засоряется ежедневными обновлениями.
- **Защита от автоотключения.** GitHub выключает запуски по расписанию, если в
  репозитории 60 дней нет активности. Workflow при каждом запуске по расписанию
  заново включает сам себя через API, что сбрасывает этот счётчик. Проверить это
  можно только временем; если запуски всё же остановятся, их включает кнопка
  Enable workflow на вкладке Actions.

Запуски по расписанию GitHub выполняет с задержкой, иногда на час и больше. Для
расписания пар это некритично.

## Структура

```
.github/workflows/         автообновление и публикация на GitHub Pages
parser/
  build_schedule.py        парсер: API -> schedule.json
  compare_ics.py           сверка schedule.json с .ics из личного кабинета
  tests/                   тесты и образец ответа API
public/schedule.json       результат (не хранится в git, его будет публиковать GitHub Actions)
```
